# pair-wise-yf-55 动态表单协作发布与版本迁移模拟器

## 源提示词摘要
业务人员在草稿里拖拽字段、设置联动规则；两人同时编辑时，后保存的人不能盖掉已发布结构。需要把发布、迁移、恢复整理成完整协作流程：草稿编辑、修订号过期提示、待合并草稿、发布前重查历史快照、迁移待办与兼容记录、发布失败回滚、未完成草稿找回；运行态表单与版本差异读同一份已发布内容。纯前端、不接后端、不新增依赖。

## 技术栈
React 19 + TypeScript + Vite + MUI + Redux Toolkit + React Hook Form + i18next + dnd-kit，localStorage 持久化。

## 协作流程

1. **编辑留在草稿版本**：字段拖拽、改名、必填切换、删除（联动规则级联清理）与规则编排都只改草稿；已发布版本只增不改。
2. **修订号过期检测**：每份草稿记录 `baseRevision`。点「模拟同事抢先发布」会让已发布修订号 +1；基于旧修订号的草稿在「发布前检查」或发布时被标记 `stale`，提示旧稿过期并阻止覆盖，已发布结构继续可看可运行。
3. **待合并草稿**：过期草稿移入「待合并草稿」页签；合并以最新已发布结构为底，仅追加草稿中新增且引用仍有效的字段/规则，生成基于最新修订号的新草稿。
4. **发布前重查历史快照**：预检按草稿即将发布的最新结构重查全部历史快照，缺少必填字段的记录进入「迁移待办」；未迁移待办重跑预检时会按最新结果重建。
5. **版本来源迁移成兼容记录**：历史快照保留不可变的 `sourceRevision`；迁移时按字段类型补默认值，生成 `fromRevision → toRevision` 的兼容记录，并在快照上标记已兼容修订号。
6. **发布失败可恢复**：打开「下次发布失败」开关模拟写入失败，新版本不落库，已发布结构停留在之前可用版本，页面顶部提示并可一键恢复；草稿保留，重试即可发布。
7. **未完成草稿找回**：所有改动实时写入 localStorage，重新打开页面时自动找回进行中的草稿（可继续编辑或丢弃）。
8. **单一已发布数据源**：`selectPublishedVersion` 是唯一入口，运行态表单（含联动显示/必填）、已发布结构页和版本差异页都读同一份内容，草稿改动在发布前不影响运行态。

## 验证
```bash
npm run smoke   # 协作全流程冒烟：过期检测/待合并/迁移兼容/失败回滚/发布
npm run build   # 类型检查 + 构建
```

```bash
npm install
npm run dev
```
